# critic-and-fuzzy — 判分 schema、聚合与模糊标准处理

配套 skills/evo/SKILL.md「判分与模糊标准」一节。写阶段提示词（critic）时按本文档组织。

## verdict schema（critic 输出，严格照此）

```json
{
  "score": 7.5,
  "verdict": "accept",
  "summary": "一句总评",
  "strengths": ["可观察的优点"],
  "weaknesses": ["可观察的不足"],
  "risks": ["潜在的长期风险"],
  "regressionConcerns": ["可能弄坏既有行为的事项"],
  "perCriterion": [
    { "criterion": "标准1的名字", "score": 8.0, "note": "证据/依据" },
    { "criterion": "标准2的名字", "score": 6.5, "note": "证据/依据" }
  ]
}
```

- `score` 0–10，整体分（不是各条平均，允许权重直觉）。
- `verdict` 三态：accept = 可作新 champion；revise = 方向对但欠火候；reject = 无帮助。
- 除 `summary` 外，所有字符串字段写**可观察证据**（引用候选里的具体句子/行为），
  不写形容词堆砌。critic 提示词里要求：**无法用证据支撑的批评不要写**。

## 聚合规则（select 阶段，确定性）

1. 每候选均分 `mean`；拒绝数 `rejects`；接受数 `accepts`；极差 `spread = max-min`。
2. 入选条件（全部满足才入选）：
   - `mean >= threshold`（默认 7）
   - `rejects == 0`（reject 一票否决）
   - `mean > championScore`（冠军地板，严格大于）
3. 平局：按 spread 小的优先；仍平 → 提案更小的优先（最小改动原则）。
4. 无候选满足 → 无人当选，champion 不变。

## 模糊标准的三条规则（核心）

| # | 规则 | 说明 |
|---|---|---|
| 1 | 量化为先 | 能手写「可观察表现」就写：「无’首先/其次/最后’式套话、无’值得注意的是’、句子长短混合、具体数字胜于空泛形容词」。 |
| 2 | 模糊也合法 | 真无法量化（「更有灵气」）时，critic 用语言理解判分但**必须引用候选原文为证据**；标准文件里把这条标成「主观标准」，并给 2–3 个判断锚点（什么算好/坏的例子）。 |
| 3 | 分歧升级 | 入选者 spread ≥ 3 → 停，回元层对话请用户裁定；用户裁定写成一条**新标准**（转成规则 1 形态）追加进 criteria.md——这本身就是 L2 进化，**必须用户确认后才落盘**。 |

## 为什么 critic 要独立、互不可见

- 独立判断避免「从众」：三个 critic 看同一候选，意见不同恰好暴露标准模糊。
- critic 之间不交流；每个 critic 只拿到：标准 + baseline + 这一个候选 + CHANGELOG。
- 评审和实现分离（actor ≠ critic）：评审者没有「我写的就得护着」的偏向。
- 元层（你）也不在 critic 阶段插话——你对结果的解读放在 select 之后，
  那才是人/元层的主场。

## 落盘要求

每个 critic 尽量把 verdict JSON 写到
`runs/<round>/candidate-<i>/verdict-<k>.json`（与返回内容一致）。审计时
`ledger.md` 只记结论，明细全在候选目录里。

## 示例：把模糊标准拆成可观察形态

| ❌ 模糊 | ✅ 可观察（规则 1 形态） |
|---|---|
| 语气更自然 | 无「首先/其次/最后/综上所述」套话；无「值得注意的是」「在当今…背景下」；句子平均长度与最短/最长句差 > 2 倍 |
| 更有说服力 | 每个论点后 1–2 句证据或例子；无话术空转（如「我们坚信…」后无下文） |
| 更像人写的 | 有具体细节和数字；允许口语化的连接（「但」「其实」）；不全是完整句式 |
